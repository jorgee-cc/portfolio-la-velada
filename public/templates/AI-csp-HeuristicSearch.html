01 · Contexto del proyecto

Dos problemas clásicos de IA,
dos paradigmas de resolución

El repositorio agrupa dos trabajos independientes de la asignatura de Inteligencia Artificial Aplicada. El primero modela el puzzle lógico Binairo (Takuzu) como un Problema de Satisfacción de Restricciones (CSP) resuelto con python-constraint. El segundo implementa un motor de búsqueda de caminos más cortos en C++ que aplica A* sobre mapas de carreteras reales de Estados Unidos en formato DIMACS, con hasta 24 millones de nodos.

El foco técnico del segundo módulo está en el diseño de estructuras de datos de bajo nivel: una lista abierta implementada como Bucket Queue (algoritmo de Dial) que amortiza inserciones a O(1), y una heurística de Haversine que garantiza admisibilidad y consistencia sobre coordenadas geográficas reales.

El proyecto incluye además una herramienta de análisis estadístico de grafos (analizar_grafo.py) que genera consultas de prueba por percentiles de distancia, evitando el sesgo de una selección aleatoria simple a la hora de evaluar el rendimiento del algoritmo.

04 · Parte 1 — Binairo como CSP

Balance, no-consecutividad
y arco-consistencia generalizada

El tablero se modela con una variable de decisión por casilla vacía, dominio binario {0,1} y cuatro restricciones aplicadas a cada fila y columna.

Modelado (X, D, C)
X = {x₁ … xₘ} → casillas vacías (m variables) D = {0, 1} → dominio de cada variable C → 4 restricciones por fila/columna: Σ yᵢ,ⱼ = n/2 (balance, fila i) Σ yᵢ,ⱼ = n/2 (balance, columna j) 0 < yᵢ,ⱼ+yᵢ,ⱼ₊₁+yᵢ,ⱼ₊₂ < 3 (fila) 0 < yᵢ,ⱼ+yᵢ₊₁,ⱼ+yᵢ₊₂,ⱼ < 3 (columna)

Las restricciones ternarias se implementan con FunctionConstraint de python-constraint, aplicando GAC (Generalized Arc Consistency): la arco-consistencia clásica solo maneja restricciones binarias, por lo que fue necesario generalizarla a restricciones de n variables.

05 · Parte 2 — Búsqueda A* sobre carreteras reales

Espacio de estados, heurística
admisible y consistente

El agente se mueve por un grafo dirigido ponderado G=(V,E,w). Cada estado es, simplemente, el vértice donde se encuentra el agente.

Espacio de estados
S = V = {0, 1, …, N-1} S₀ = v_inicio Meta(s) ⟺ s = v_fin Operador Mover(s, v): Precondición: (s, v) ∈ E Postcondición: s ← v Coste: w(s, v) ∈ ℝ⁺

El espacio de estados es isomorfo al conjunto de vértices del grafo: la única variable que cambia durante la búsqueda es la posición del agente.

Heurística de Haversine — admisible y consistente
a = sin²(Δφ/2) + cos(φₙ)·cos(φ_fin)·sin²(Δλ/2) h(n) = 2R · atan2(√a, √(1-a)) R ≈ 6.371.000 m

Al asumir desplazamiento en línea recta sobre la esfera terrestre —ignorando que el agente solo puede moverse por carreteras—, el coste estimado nunca supera al real: h(n) ≤ h*(n). Esto garantiza que A* no reabra nodos ya cerrados.

Bucket Queue (algoritmo de Dial)

En lugar de un heap binario, la lista abierta usa un vector circular de tamaño C+1 (C = peso máximo de arista), donde cada posición es una lista de nodos con el mismo valor f = g + h.

indice = f % (C + 1) insertar(): O(1) sacarMejor(): O(C) amortizado

Un mapa hash (mejorF) evita insertar duplicados con peor coste que el ya conocido para un nodo.

¿Por qué A* y no otras alternativas?

Se descartaron búsquedas voraces y DFS por no garantizar optimalidad. También se descartó IDA*: al tener costes continuos (metros reales, no una escala pequeña de enteros), regeneraría el árbol de búsqueda de forma ineficiente en cada iteración de profundización.

La propia implementación permite desactivar la heurística (h(n)=0), degradando A* a Dijkstra puro (búsqueda de coste uniforme) — así es como se generaron todos los datos comparativos de la siguiente sección.

07 · Retos técnicos

Decisiones de bajo nivel
para procesar grafos masivos

RETO 01
Carga en dos pasadas para pre-asignar memoria
Redimensionar el vector de adyacencia en cada arista provocaría realocaciones y copias masivas en grafos de millones de nodos. La solución lee el fichero .gr dos veces: primero para hallar el ID de nodo más alto, luego reserva el tamaño exacto antes de guardar las aristas.
// PASO 1: solo detectar el nodo máximo while (getline(archivo, linea)) { // ... actualizar maxNodoVisto } // PASO 2: reserva exacta, una sola vez vectorAdyacencia.resize(maxNodoVisto + 1); coordenadas.resize(maxNodoVisto + 1); // PASO 3: relectura y almacenamiento real archivo.clear(); archivo.seekg(0);
RETO 02
Bucket Queue circular sin árbol de prioridad
Un heap binario clásico da O(log n) por operación. Al ser los costes enteros y acotados por el peso máximo de arista, un vector circular de tamaño C+1 permite inserción O(1) y extracción O(C) amortizada, evitando duplicados con un mapa de mejor coste conocido.
void insertar(int id, int f) { auto it = mejorF.find(id); if (it == mejorF.end() || f < it->second) { mejorF[id] = f; int indice = f % tamañoCircular; // wrap-around buckets[indice].push_back(id); elementos++; } }
RETO 03
Heurística geodésica sobre coordenadas en microgrados
Los ficheros DIMACS almacenan latitud/longitud como enteros multiplicados por 10⁶. Antes de aplicar Haversine hay que convertir microgrados → grados → radianes, y devolver la distancia como entero para que encaje en la aritmética modular del Bucket Queue.
double lat1 = c1.latitud * M_PI / 180000000.0; double a = sin(dlat/2)*sin(dlat/2) + cos(lat1)*cos(lat2)*sin(dlon/2)*sin(dlon/2); double c = 2 * atan2(sqrt(a), sqrt(1-a)); return static_cast<int>(RADIO_TIERRA * c);
RETO 04
GAC con restricciones ternarias en Binairo
Las restricciones de fila/columna involucran N variables simultáneas: ni la arco-consistencia clásica (binaria) ni la camino-consistencia (rutas de longitud 2) se aplican. La solución usa FunctionConstraint, que evalúa la restricción como una función pura sobre N argumentos.
def balance_constraint(*row): N = len(row) return sum(row) == N // 2 problem.addConstraint( FunctionConstraint(balance_constraint), row_vars)
RETO 05
Consultas de prueba sin sesgo aleatorio
Un muestreo aleatorio simple podría sobrerrepresentar rutas cortas y no exponer el peor caso de la heurística. El script analiza 1.000 pares candidatos, calcula percentiles de distancia (P10/P40-60/P75-95) y busca explícitamente la diagonal más larga entre las esquinas del bounding box del mapa.
# Q4: caso adversarial — diagonal más larga diagonales = [('SW','NE'), ('SE','NW')] for esq1, esq2 in diagonales: dist = calcular_distancia_haversine(...) if dist > mejor_dist_diagonal: mejor_diagonal = (nodo1, nodo2)
RETO 06
Aislar el tiempo del algoritmo del I/O de disco
En las primeras ejecuciones, el tiempo total incluye la lectura del fichero desde disco. En ejecuciones posteriores, el page cache del sistema operativo mantiene los datos en memoria volátil, por lo que el tiempo medido con chrono refleja casi exclusivamente el coste computacional puro del algoritmo.
auto t0 = chrono::high_resolution_clock::now(); algoritmo.dijkstra(grafo, inicio, fin); auto t1 = chrono::high_resolution_clock::now(); // arranque en caliente → tiempo puro de búsqueda
08 · Limitaciones

Dónde se rompe el diseño

Tamaño del Bucket Queue ligado al peso máximo
El vector circular de la lista abierta se dimensiona según el peso de arista más alto del grafo. Un grafo mal definido con una arista de coste anómalamente alto reservaría mucha más memoria de la necesaria.
Binairo exige dimensión N par
El solver lanza una excepción si se le pasa una matriz de dimensión impar, ya que las restricciones de balance (N/2 fichas de cada color) no están definidas para N impar.
Crecimiento superlineal del tiempo con la profundidad
Aunque el throughput por nodo es estable, el tiempo total crece más rápido que el tamaño del grafo: pasar de NY a EE.UU. (90× más nodos) implica rutas con mayor profundidad d, y A* explora O(b*)^d nodos.
La heurística pierde toda su ventaja en diagonal
En consultas DIAGONAL, la red de carreteras en rejilla y barreras geográficas (p. ej. Sierra Nevada en California) hacen que Haversine subestime tanto el coste real que deja de discriminar entre nodos.
09 · Aprendizajes y mejoras futuras

De la heurística admisible
a la búsqueda bidireccional

Heurísticas ALT (A*, Landmarks, Triangle inequality)
Preprocesar el grafo seleccionando nodos "landmark" y precalculando distancias exactas desde y hacia ellos permitiría cotas más ajustadas que la línea recta de Haversine, especialmente en consultas diagonales.
Búsqueda bidireccional
Ejecutar A* simultáneamente desde el origen y desde el destino reduciría la profundidad efectiva a d/2 en cada dirección: en teoría, 2(b*)^(d/2) nodos frente a (b*)^d, una mejora relevante en rutas de larga distancia.
La distribución de datos importa tanto como su cantidad
En Binairo, dos tableros con idéntico número de variables de decisión dieron tiempos de resolución muy distintos (11 min vs. 65 min): el orden en que el solver descarta combinaciones inválidas es tan determinante como el tamaño del problema.
Diseñar el experimento, no solo el algoritmo
Construir analizar_grafo.py para generar consultas por percentiles —en vez de pares aleatorios— fue tan importante para el análisis como la propia implementación de A*: sin ello, el colapso de la heurística en diagonales podría haber pasado inadvertido.
